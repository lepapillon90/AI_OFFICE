# AI 오피스 전체 로드맵

## 제품 목표

사람과 AI 직원이 같은 픽셀 오피스 공간에서 일하고, 대화하고, 업무 상태와 결과를 확인하는 웹 기반 가상 오피스입니다.

## Phase 1 — 가상 오피스 기본 이동 ✅

- Flutter Web + Flame 오피스 맵
- 플레이어 캐릭터, 카메라 추적, WASD·방향키 이동
- 벽·책상 충돌
- 바닥·벽·가구 픽셀 에셋

완료 기준: 브라우저에서 캐릭터가 오피스를 자유롭게 이동하고 장애물을 통과하지 않습니다.

## Phase 2 — 오브젝트 상호작용 ✅

- 컴퓨터 가까이에서 `[E] 컴퓨터 사용` 안내
- E 키로 개발 AI 컴퓨터 팝업 열기
- 팝업: 개발 AI, 대기 중, 업무 지시, 대화하기, 작업 확인
- ESC·닫기 버튼으로 게임으로 돌아가기

완료 기준: 컴퓨터를 사용하고 닫은 뒤 다시 캐릭터를 이동할 수 있습니다. 실제 AI 연결은 하지 않습니다.

## Phase 3 — NPC와 AI 직원 표현 ✅

- AI 직원 NPC와 자리 배정
- 대기·작업 중·회의 중·오류 상태 표시
- NPC 머리 위 상태 문구와 상태 색상
- 컴퓨터와 AI 직원 연결

완료 기준: 각 컴퓨터가 한 AI 직원과 연결되고 현재 상태가 맵에서 보입니다.

## Phase 4 — 회사 데이터와 계정 ✅

- Supabase Auth 로그인 (아이디+비밀번호, 내부적으로 이메일 매핑)
- 회사·직원 데이터 모델 및 RLS, owner/hr_manager/member 역할 (`docs/PHASE4_SUPABASE.md`)
- 직원 역할과 AI 제공자 설정 저장
- 오피스 레이아웃 저장 (이연)

완료 기준: 로그인한 사용자가 자신의 회사와 직원 구성을 저장·복원합니다.

실제 계정으로 검증 완료: 회원가입 → 직원 정보 수정 → 로그아웃 → 재로그인 후에도 수정 내용이 그대로 복원됨을 확인.

## Phase 5 — 멀티플레이와 채팅 🚧

- Supabase Realtime으로 사용자 위치 공유 ✅
- 같은 공간의 다른 사용자 표시 ✅ (같은 층에 있을 때만 렌더링)
- 공간 채팅 ✅ (Realtime Broadcast + `messages` 테이블, `docs/PHASE5_MULTIPLAYER.md`)
- 아이디로 구성원 초대 ✅ — 실제 계정으로 검증 완료(`invites` 테이블, 대표·인사관리자가 역할 지정해 초대 → 로그인 시 자동 합류, `docs/PHASE4_SUPABASE.md`)
- 직원별 대화 기록 ✅ — `messages` 테이블의 귓속말·AI 탭 기록 + Phase 6의 `NpcTask` 작업 이력

완료 기준: 두 사용자가 같은 회사 오피스에서 서로의 이동과 채팅을 실시간으로 확인합니다.

Realtime Presence로 검증 완료(가짜 두 번째 사용자를 같은 채널에 연결해 실제 브라우저 세션에 실시간으로 나타남을 확인). 채팅은 로컬 전송·서버 브로드캐스트 응답, 그리고 내가 보내는 귓속말이 다른 사용자에게 정확히 도달하는 것까지 확인했으나, **다른 사람이 보낸 메시지를 내가 실시간으로 수신하는 경로만 이 자동화 브라우저 환경에서 재현 안 됨**(같은 세션·같은 채널에서 presence 수신은 되는데 채팅 브로드캐스트 수신만 안 됨 — 코드 문제라기보다 이 테스트 환경 특유의 현상으로 보임, `docs/STATUS.md` 참고). 실제 브라우저(또는 폰) 두 개로 최종 확인 권장.

## Phase 6 — AI 직원 업무 실행 ✅ (완료)

- AI 제공자 연결(OpenAI 등) ✅ — `@AI직원이름 명령` → Supabase Edge Function(`ask-employee`)이 OpenAI API를 서버 사이드에서 호출, 응답을 채팅에 표시 (`docs/PHASE6_AI_EMPLOYEES.md`), 실제 API 키로 검증 완료
- 컴퓨터 팝업(`[E]` 상호작용) 연동 ✅ — "대화하기"가 팝업을 닫고 그 직원의 채팅방(귓속말·AI 탭)을 바로 열어줌, "작업 이력"이 그 직원의 명령/결과 이력을 보여줌. 자동 테스트(`test/computer_popup_npc_chat_test.dart`)로 검증 완료(이 세션 브라우저 환경에서 키보드 이동이 불안정해 실제 클릭 이동으로는 확인 못함)
- 직원별 역할·시스템 지시·업무 컨텍스트 ✅ — 직원 이름·역할을 프롬프트에 반영하고, 그 직원과 나눈 최근 대화(최대 6턴)도 `history`로 함께 전달해 맥락 있는 답변을 유도. 재배포한 Edge Function을 직접 호출해 맥락 반영을 실제로 검증(`docs/PHASE6_AI_EMPLOYEES.md`)
- 업무 진행 상태·결과의 구조화된 기록·오류/재시도·사용량 기록 ✅ — `OfficeGame.tasksFor(employee)`가 명령/상태/결과/시도 횟수를 `NpcTask`로 기록, 실패 시 자동 재시도 1회 후에도 실패해야 "오류" 전환, `usageFor`/`totalUsage`가 호출 횟수·성공/실패·토큰 사용량을 집계
- `NpcTask`/사용량의 Supabase 영속화 ✅ — `npc_tasks`/`npc_usage_events` 테이블(SQL은 `docs/PHASE6_AI_EMPLOYEES.md`)에 매 변경을 저장하고, 로그인 시 불러와 복원 — **사용자가 아직 그 SQL을 Supabase에서 실행하지 않았다면 이 부분만 미완료**(실행 전엔 세션 메모리에만 유지, 앱은 정상 동작)
- 가상 문서 생성(실제 업무 수행) ✅ — 성공한 명령마다 결과를 텍스트 문서로 Supabase Storage(`npc-documents` 버킷)에 저장, "작업 이력"에서 "문서 열기"로 열람 — 실제 OS 파일시스템 접근이 아닌 앱 내 저장 문서

완료 기준: 사용자가 컴퓨터 팝업에서 업무를 지시하고 AI 직원의 결과를 확인합니다. — **충족**. 아래는 의도적으로 범위 밖에 남겨둔 것들:
- AI 직원이 외부 시스템을 실제로 조작(캘린더 등록, 다른 서비스 API 호출 등) — 텍스트 응답 + 가상 문서까지만 제공
- ~~실제 비용(통화) 환산, 사용량 상한/경고~~ — `docs/PHASE7_OPS_REVIEW.md`의 후속 반영에서 완료(USD 비용 표시, 사용량 한도 초과 시 재시도 없이 안내)
- 귓속말의 DB 레벨 프라이버시(RLS) — 지금은 화면에서만 숨김

## Phase 7 — 협업 기능과 운영 ✅ (완료)

- 알림과 활동 기록 ✅ — 직원 정보 수정, AI 직원 명령 성공/실패를 `OfficeGame.activityLog`에 기록하고 화면 우측 상단 알림(🔔) 아이콘에 안 읽은 개수 배지로 표시(`docs/PHASE7_ACTIVITY.md`). `activity_events` 테이블에 영속화(마이그레이션 필요), 자동 테스트(`test/activity_log_test.dart`)로 검증
- 프로젝트·업무 보드 연결 ✅ — 할 일/진행 중/완료 3칸 칸반 보드(`docs/PHASE7_BOARD.md`), 카드를 AI 직원에게 배정하면 "AI에게 지시" 버튼으로 그 직원 채팅방에 카드 제목을 `@멘션` 명령으로 바로 전송(기존 Phase 6 파이프라인 재사용 — 재시도/작업 이력/사용량 집계 그대로 적용됨). 카드 생성/이동/배정/삭제가 활동 기록에도 남음. `board_tasks` 테이블에 영속화(마이그레이션 필요), 자동 테스트(`test/board_test.dart`)로 검증 + 실제 브라우저 클릭으로 생성→이동→삭제까지 확인
- 회의실·회의 진행 UI ✅ — 2층 회의실 파티션 안에 회의 테이블(`[E]` 상호작용, `docs/PHASE7_MEETING.md`), 참석자(AI 직원) 선택 → 회의 시작(각자 상태를 "회의 중"으로) → 진행 중 화면(참석자·경과 시간) → 회의 종료(상태 복원). 시작/종료가 활동 기록에 남음, 새 DB 테이블 불필요(기존 활동 기록 테이블 재사용, 진행 중인 회의 자체는 세션 메모리에만 있음). 자동 테스트(`test/meeting_test.dart`)로 검증
- 관리자 화면, 감사 기록, 권한 강화 ✅ — 대표 전용 관리자 화면(구성원 목록·역할 변경), 활동 기록에 행위자(`actor_name`) 추가로 "누가" 했는지 남김, 인사관리자의 인사관리자 초대 권한 상승 구멍을 서버(RLS)·클라이언트 양쪽에서 막음(`docs/PHASE7_ADMIN.md`). 자동 테스트(`test/company_role_test.dart`, `test/activity_log_test.dart`)로 검증 + 진행 중 `activity_events`의 type 체크 제약이 board/meeting을 허용하지 않던 버그도 함께 발견·수정
- 성능·보안·배포 운영 점검 ✅ — 새 기능보다는 코드 리뷰 기반 점검(`docs/PHASE7_OPS_REVIEW.md`). 실제로 고친 것: (1) `ask-employee` Edge Function이 호출자가 그 회사 구성원인지 전혀 확인하지 않던 것 → 확인 로직 추가, (2) 같은 함수에 회사당 5분/30회 사용량 상한 추가(비용 통제), (3) 명령/대화 맥락 길이의 서버 쪽 상한 추가(클라이언트 우회 방지), (4) 로그인 시 7개 쿼리를 순차 실행하던 것 → `Future.wait`로 병렬화(로그인 지연시간 단축), (5) 업무 보드 조회에 조회 상한 누락 → 최근 500건으로 제한
- 후속 반영(위 점검의 권장 사항 중 구현) ✅ — (1) AI 직원 사용량을 gpt-4o-mini 단가 기준 USD로 환산해 표시, (2) 사용량 한도(429) 응답을 별도 예외로 구분해 재시도·집계 없이 안내, (3) `activity_events`에 안정적인 `actor_user_id` 추가, (4) `MultiplayerChannel`을 `private: true`로 전환하고 `realtime.messages` RLS 정책으로 Realtime Authorization 적용 — 실제 라이브 호출로 "회사 구성원만 구독 가능, 남의 회사 채널은 거절" 검증 완료, (5) 웹 렌더러는 Flutter 3.47.4 기준 CanvasKit이 이미 기본/유일 렌더러임을 확인(코드 변경 불필요). **의도적으로 제외**: Vercel 빌드 캐시(대시보드 설정 필요, 코드만으로 확인 불가)
- 후속 반영 2(남은 이연 minor 항목) ✅ — (1) `activity_read_marks` 테이블로 "마지막으로 읽은 시각"을 서버에 저장해 안 읽음 배지가 재로그인 후에도 정확히 복원되도록 함, (2) 업무 보드 카드에 설명 편집 UI 추가(모델·DB는 이미 지원), (3) 업무 보드에 드래그 앤 드롭 추가(`Draggable`/`DragTarget`, 기존 버튼 이동과 공존) — 실제 브라우저 검증 중 "새 업무" 다이얼로그의 제목 입력이 "추가" 버튼을 활성화하지 못하던 실제 버그를 발견해 함께 수정(`docs/PHASE7_ACTIVITY.md`, `docs/PHASE7_BOARD.md`)

완료 기준: 팀이 가상 오피스를 실제 협업 공간으로 안정적으로 사용할 수 있습니다. — **충족**. Phase 7의 5개 항목 모두 완료.

## Phase 8 — 실제 업무 연동과 협업 고도화 🚧

Phase 7까지로 로드맵 원안은 완료되었고, 이후 사용자와 논의해 정한 다음 방향입니다. 계획된 하위 항목:

- 파일 업로드/공유 ✅ — 채팅에서 실제 파일을 첨부해 공유(`docs/PHASE8_FILE_SHARING.md`), `chat-attachments` Storage 버킷, 자동 테스트(`test/chat_attachment_test.dart`)로 업로드/실패/AI 방 오발송 방지 검증
- 외부 서비스 연동(Slack 웹훅) ✅ — 활동 기록에 남는 모든 이벤트를 회사가 등록한 Slack 채널로 전송(`docs/PHASE8_SLACK.md`), 실제 Slack 호출은 새 Edge Function(`notify-slack`)이 서버 사이드에서 수행(CORS/URL 노출 방지), 관리자 화면에 대표 전용 웹훅 설정 UI, 자동 테스트(`test/notify_slack_test.dart`)로 전달·미설정 시 no-op·전송 실패가 활동 기록에 영향 없음을 검증
- 회의실 예약/캘린더 — 미착수
- 협업 강화(사람에게 업무 배정, 실시간 동기화) — 미착수
- 온보딩/UX 다듬기 — 미착수
- 운영/관리 강화 ✅ (구성원 강퇴 · 감사 기록 필터/검색) — 관리자 화면 구성원 목록에 "구성원 제거" 버튼 추가(대표 전용, 확인 다이얼로그, 계정은 유지하고 회사 소속만 해제), 활동 기록 패널에 유형별 필터 칩과 메시지·행위자 텍스트 검색 추가(`docs/PHASE7_ADMIN.md`), 자동 테스트(`test/activity_panel_test.dart`)로 필터·검색 조합 검증
- 회사 컴퓨터 원격 명령(터미널 열기 · 폴더 만들기, 직원별 다중 컴퓨터 지정) ✅ — 채팅에서 `@서버 터미널 열어줘`처럼 말하면 회사 기본 컴퓨터에서, `@도윤 터미널 열어줘`처럼 컴퓨터 연결된 특정 직원에게 말하면 그 직원 자리 컴퓨터에서 실제로 실행(`docs/PHASE8_REMOTE_AGENT.md`). 브라우저가 로컬 파일시스템에 접근할 수 없다는 제약 때문에, 그 컴퓨터에서 상시 실행되는 별도 로컬 에이전트(`bin/remote_agent.dart`, 순수 `dart:io`만 사용해 `pubspec.yaml` 의존성 추가 없이 동작, `--agent-key`로 담당 컴퓨터 구분)가 대신 수행 — 임의 명령이 아니라 미리 정한 화이트리스트(`open_terminal`/`create_folder`/`open_terminal_claude` — 마지막은 터미널을 열면서 `claude` CLI 하나만 곧바로 실행)만 허용, 직원별 연결도 관리자 화면에서 직원마다 명시적으로 켜야만(옵트인) 적용되어 평소 업무 대화가 실수로 가로채이지 않음. 자동 테스트(`test/remote_command_test.dart`) 12개로 명령 파싱·화이트리스트 밖 명령 거절·미설정 시 안내·컴퓨터 연결/미연결 직원의 라우팅 분기 검증
- **별도 연구 트랙으로 분리**: PM NPC가 API 호출 대신 실제 터미널에 붙어 Claude CLI로 개발 업무를 수행하는 아이디어 — Edge Function(서버리스) 구조로는 불가능하고 상시 실행 컨테이너·샌드박싱·구독 인증 유지 등 별도 인프라가 필요해, Phase 8 본 트랙과 분리해 나중에 설계부터 다시 검토하기로 함. (위 "회사 컴퓨터 원격 명령"이 같은 방향의 훨씬 좁은 버전 — 상시 실행 로컬 에이전트라는 인프라는 실제로 구현했지만, AI가 자유롭게 셸 명령을 내리는 게 아니라 미리 정한 화이트리스트 두 개(`open_terminal`/`create_folder`)만 허용하는 것으로 범위를 크게 좁혀서 이 분리된 아이디어와는 별개로 진행함)

## 원칙

- 한 단계의 완료 기준을 검증한 뒤 다음 단계로 이동합니다.
- AI·실시간·인증 기능은 UI와 상태 모델이 안정된 뒤 연결합니다.
- 사용자 데이터와 AI API 키는 클라이언트에 저장하지 않습니다.

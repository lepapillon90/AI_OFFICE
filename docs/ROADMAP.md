# AI 오피스 전체 로드맵

## 제품 목표

사람과 AI 직원이 같은 픽셀 오피스 공간에서 일하고, 대화하고, 업무 상태와 결과를 확인하는 웹 기반 가상 오피스입니다.

## Phase 1 — 가상 오피스 기본 이동 ✅

- Flutter Web + Flame 오피스 맵
- 플레이어 캐릭터, 카메라 추적, WASD·방향키 이동
- 벽·책상 충돌
- 바닥·벽·가구 픽셀 에셋

완료 기준: 브라우저에서 캐릭터가 오피스를 자유롭게 이동하고 장애물을 통과하지 않습니다.

## Phase 2 — 오브젝트 상호작용 ✅

- 컴퓨터 가까이에서 `[E] 컴퓨터 사용` 안내
- E 키로 개발 AI 컴퓨터 팝업 열기
- 팝업: 개발 AI, 대기 중, 업무 지시, 대화하기, 작업 확인
- ESC·닫기 버튼으로 게임으로 돌아가기

완료 기준: 컴퓨터를 사용하고 닫은 뒤 다시 캐릭터를 이동할 수 있습니다. 실제 AI 연결은 하지 않습니다.

## Phase 3 — NPC와 AI 직원 표현 ✅

- AI 직원 NPC와 자리 배정
- 대기·작업 중·회의 중·오류 상태 표시
- NPC 머리 위 상태 문구와 상태 색상
- 컴퓨터와 AI 직원 연결

완료 기준: 각 컴퓨터가 한 AI 직원과 연결되고 현재 상태가 맵에서 보입니다.

## Phase 4 — 회사 데이터와 계정 ✅

- Supabase Auth 로그인 (아이디+비밀번호, 내부적으로 이메일 매핑)
- 회사·직원 데이터 모델 및 RLS, owner/hr_manager/member 역할 (`docs/PHASE4_SUPABASE.md`)
- 직원 역할과 AI 제공자 설정 저장
- 오피스 레이아웃 저장 (이연)

완료 기준: 로그인한 사용자가 자신의 회사와 직원 구성을 저장·복원합니다.

실제 계정으로 검증 완료: 회원가입 → 직원 정보 수정 → 로그아웃 → 재로그인 후에도 수정 내용이 그대로 복원됨을 확인.

## Phase 5 — 멀티플레이와 채팅 🚧

- Supabase Realtime으로 사용자 위치 공유 ✅
- 같은 공간의 다른 사용자 표시 ✅ (같은 층에 있을 때만 렌더링)
- 공간 채팅 ✅ (Realtime Broadcast + `messages` 테이블, `docs/PHASE5_MULTIPLAYER.md`)
- 아이디로 구성원 초대 ✅ — 실제 계정으로 검증 완료(`invites` 테이블, 대표·인사관리자가 역할 지정해 초대 → 로그인 시 자동 합류, `docs/PHASE4_SUPABASE.md`)
- 직원별 대화 기록 ✅ — `messages` 테이블의 귓속말·AI 탭 기록 + Phase 6의 `NpcTask` 작업 이력

완료 기준: 두 사용자가 같은 회사 오피스에서 서로의 이동과 채팅을 실시간으로 확인합니다.

Realtime Presence로 검증 완료(가짜 두 번째 사용자를 같은 채널에 연결해 실제 브라우저 세션에 실시간으로 나타남을 확인). 채팅은 로컬 전송·서버 브로드캐스트 응답, 그리고 내가 보내는 귓속말이 다른 사용자에게 정확히 도달하는 것까지 확인했으나, **다른 사람이 보낸 메시지를 내가 실시간으로 수신하는 경로만 이 자동화 브라우저 환경에서 재현 안 됨**(같은 세션·같은 채널에서 presence 수신은 되는데 채팅 브로드캐스트 수신만 안 됨 — 코드 문제라기보다 이 테스트 환경 특유의 현상으로 보임, `docs/STATUS.md` 참고). 실제 브라우저(또는 폰) 두 개로 최종 확인 권장.

## Phase 6 — AI 직원 업무 실행 ✅ (완료)

- AI 제공자 연결(OpenAI 등) ✅ — `@AI직원이름 명령` → Supabase Edge Function(`ask-employee`)이 OpenAI API를 서버 사이드에서 호출, 응답을 채팅에 표시 (`docs/PHASE6_AI_EMPLOYEES.md`), 실제 API 키로 검증 완료
- 컴퓨터 팝업(`[E]` 상호작용) 연동 ✅ — "대화하기"가 팝업을 닫고 그 직원의 채팅방(귓속말·AI 탭)을 바로 열어줌, "작업 이력"이 그 직원의 명령/결과 이력을 보여줌. 자동 테스트(`test/computer_popup_npc_chat_test.dart`)로 검증 완료(이 세션 브라우저 환경에서 키보드 이동이 불안정해 실제 클릭 이동으로는 확인 못함)
- 직원별 역할·시스템 지시·업무 컨텍스트 ✅ — 직원 이름·역할을 프롬프트에 반영하고, 그 직원과 나눈 최근 대화(최대 6턴)도 `history`로 함께 전달해 맥락 있는 답변을 유도. 재배포한 Edge Function을 직접 호출해 맥락 반영을 실제로 검증(`docs/PHASE6_AI_EMPLOYEES.md`)
- 업무 진행 상태·결과의 구조화된 기록·오류/재시도·사용량 기록 ✅ — `OfficeGame.tasksFor(employee)`가 명령/상태/결과/시도 횟수를 `NpcTask`로 기록, 실패 시 자동 재시도 1회 후에도 실패해야 "오류" 전환, `usageFor`/`totalUsage`가 호출 횟수·성공/실패·토큰 사용량을 집계. 단, 이 기록들은 세션 메모리에만 있고 Supabase 영속화는 이연

완료 기준: 사용자가 컴퓨터 팝업에서 업무를 지시하고 AI 직원의 결과를 확인합니다. — **충족**. 아래는 의도적으로 범위 밖에 남겨둔 것들:
- AI 직원의 실제 업무 수행(파일 생성, 외부 도구 호출) — 텍스트 응답만 제공
- `NpcTask`/사용량 기록의 Supabase 영속화, 실제 비용(통화) 환산
- 귓속말의 DB 레벨 프라이버시(RLS) — 지금은 화면에서만 숨김

## Phase 7 — 협업 기능과 운영

- 회의실·회의 진행 UI
- 프로젝트·업무 보드 연결
- 알림과 활동 기록
- 관리자 화면, 감사 기록, 권한 강화
- 성능·보안·배포 운영 점검

완료 기준: 팀이 가상 오피스를 실제 협업 공간으로 안정적으로 사용할 수 있습니다.

## 원칙

- 한 단계의 완료 기준을 검증한 뒤 다음 단계로 이동합니다.
- AI·실시간·인증 기능은 UI와 상태 모델이 안정된 뒤 연결합니다.
- 사용자 데이터와 AI API 키는 클라이언트에 저장하지 않습니다.

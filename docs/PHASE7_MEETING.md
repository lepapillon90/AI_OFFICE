# Phase 7 (일부) — 회의실·회의 진행 UI

2층 업무공간의 회의실 파티션(`OfficeLayout.blockers`의 "Meeting-room partition") 안에 회의 테이블을 뒀습니다. `[E]`로 상호작용합니다 — 컴퓨터·엘리베이터와 같은 방식.

## 필요한 설정

**없음.** 새 DB 테이블이 필요 없습니다 — 회의 시작/종료는 이미 있는 `activity_events` 테이블(`docs/PHASE7_ACTIVITY.md`)에 기록만 남기고, 회의 자체(누가 참석 중인지, 언제 시작했는지)는 세션 메모리에만 있는 상태입니다.

## 앱 동작

1. 회의실 근처에서 `[E]` → 회의 중이 아니면 참석자 선택 화면, 회의 중이면 현재 참석자·경과 시간 화면
2. "회의 시작" — 선택한 AI 직원들의 상태를 `NpcStatus.meeting`("회의 중")으로 바꾸고(이미 있던 `_setEmployeeStatus`의 ephemeral 패턴 재사용 — `@employee` 명령의 "작업 중" 플리커와 같은 방식, Supabase에 개별 저장하지 않음), 활동 기록에 "회의가 시작되었습니다 (참석: ...)" 남김
3. "회의 종료" — 각 참석자를 회의 시작 전 상태로 되돌리고, 활동 기록에 "회의가 종료되었습니다 (참석: ..., N분 진행)" 남김
4. 동시에 하나의 회의만 진행할 수 있습니다 — 이미 진행 중일 때 `startMeeting()`을 다시 호출하면 무시됩니다
5. 층을 이동하거나(`changeFloor`) 컴퓨터/엘리베이터 팝업을 열면 회의 패널은 닫히지만, 진행 중인 회의 자체는 끝나지 않습니다 — 회의실로 돌아와 `[E]`를 다시 누르면 진행 상황을 이어서 볼 수 있습니다

## 이연된 범위

- 실제 화상/음성 통화는 없음 — 상태 표시와 참석자 관리, 활동 기록까지만
- 회의 일정 예약(캘린더)은 이번 범위 아님 — 즉석 시작/종료만 지원
- 진행 중인 회의 자체의 Supabase 영속화는 이번 범위 아님 — 새로고침하면 진행 중이던 회의는 사라짐(활동 기록의 "시작" 기록은 남지만 "종료" 기록 없이 끊김)
- 사람(팀원)을 참석자로 선택하는 기능은 이번 범위 아님 — AI 직원만 선택 가능
